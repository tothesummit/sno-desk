How it works

The model can suggest.
Only code can act.

Six steps from what you type to a fill. The line down the middle is the whole design — everything on the left can be wrong, and nothing crosses without your approval.

Model zone · can be wrong

  1. 01

    You type

    Terminal or chat to start. Voice and Telegram later.

  2. 02

    Compile

    English becomes a typed OrderIntent. The model has no broker access.

  3. 03

    Resolve

    Every ambiguity becomes an explicit field, or a question back to you.

Trust boundary

Code zone · deterministic

  1. 04

    Check

    Your rules, as data. Caps, allowlists, halts. No model in this step.

  2. 05

    Approve

    You see the ticket. Nothing routes until you say so.

  3. 06

    Route & journal

    Sent to your broker, stored with the exact words that produced it.

Security

An agent that can trade is a target.
It's designed on that assumption.

Self-hosted agents had a rough 2026: plaintext keys, poisoned skill marketplaces, instructions hidden in the pages they read. Put a brokerage account behind that and it stops being a data problem.

Two channels

News, filings, emails and web pages the agent reads are data. They can't produce an order — only you can. That's the prompt-injection boundary, enforced in the types rather than asked for in a prompt.

Keys stay in the keychain

Broker tokens live in your operating system's keychain. Never in a config file, a log, a backup or the journal. Revoke them at your broker and they're gone.

Nothing arms itself

New accounts start read-only. New agents start paused. Imported agents arrive preview-only. Turning anything on is deliberate, and countersign halt turns everything off.

ThreatWhat goes wrongDefense
Prompt injectionA filing, headline or web page contains text telling the agent to sell.Retrieved content can't create an intent. Adapters accept only approved tickets.
Misparsed instruction“Sell 100” becomes 1,000, or “half” is applied across every account.Typed fields, per-order caps, ambiguities listed on the ticket, approval every time.
Stolen credentialsA config file or backup containing broker tokens leaks.Tokens exist only in the OS keychain. Nothing credential-shaped touches disk.
Malicious shared agentSomeone shares a rule that trades against whoever imports it.Imported agents arrive paused and preview-only, and can't arm themselves.
Expired authA dead token quietly serves yesterday's positions as today's.Hard stop with a specific error. Never a cached fallback presented as live.
Tampered installA modified release or install script steals keys.Signed releases, published checksums, no piped install scripts.

Agents

Standing instructions.
Never a black box.

Write a rule once in plain English. It compiles to the same typed ticket, passes the same risk gate, and sits in one of three states you can always see.

PausedDoes nothing. Every new or imported agent starts here.
PreviewWatches its trigger and records what it would have done. Routes nothing.
ArmedActs — through the full pipeline, inside the caps you set.

Straight about it

What this is.
And what it isn't.

It is

  • Software you run. A terminal for the broker you already use.
  • Built around attack. Two channels, typed tickets, keys in the keychain.
  • Explicit. Every ambiguity becomes a field you can see before approving.
  • Open source. The design is published before the code, on purpose.

It is not

  • A broker. Your money stays where it is.
  • An adviser. It carries out your instructions. It has no opinion on what to buy.
  • A hosted service. No accounts, no custody, no credentials held for you.
  • A strategy marketplace. Shared agents arrive paused and can't arm themselves.
